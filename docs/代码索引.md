## 3. 目录约定（与机械守卫）

```
ui → app → core    依赖方向单向向下

core/              内核 + 契约实现（不得依赖 ui / Compose / Android framework）
ui/components/     公共 UI 原语（写界面前先来这儿找）
ui/plugins/builtin/  所有内置插件（一插件一文件）
ui/plugins/        共享 UI 辅助（槽位、设置面板渲染器）
ui/screens/<screen>/ 一个屏幕一个包
plugin-api/        跨模块公共契约（内核级，改动需评审 + 同步文档）
```

- `core` 的依赖边界由 **`ArchitectureGuardTest`** 机械强制（违反即单测失败）。
  确需例外（如 `core/settings` 要 `Context`）时，必须在**测试白名单里登记并同步文档**，不得默默放行。
- 同一形状（扫描源码 → 断言 → 白名单登记例外）的守卫还有三个，都挂在 `:app:testDebugUnitTest` 里：
  **`DocsConsistencyTest`**（文档与代码一致，A6）、**`SourceSizeGuardTest`**（单文件 ≤500 行，B8）、
  **`LinuxOnlyGuardTest`**（`assumeLinux()` 使用点白名单，2c）。
  它们与 `ArchitectureGuardTest` 一样：**扫到 0 个文件即失败**，「没扫到」永远不等于「没违规」。

## 4. 避免重复造轮子（原则 + 判据）

**原则**（`AGENTS.md` §10.4）：同一个概念只允许一个实现点；同一个规则若要改三处以上才能成立，
说明模型错了——先统一模型，再改调用点。

**判据（满足任意一条即需要处理）**：

- 同一个操作有两份以上实现，且**对同一输入的行为不一致**（进制、单位、边界、截断策略不同）
  → 统一到一个实现点，并在同一提交里删掉其余实现。
- 同一个 UI 原语（折叠区、设置行、面板卡、版本徽标）有两套以上渲染路径 → 同上。
- 纯代码重复、但**行为一致** → 允许先不动（三行重复优于过早抽象）；新增时优先复用已有实现。

**唯一允许的例外**：受众不同导致口径不同（面向模型的工具输出 vs 面向用户的界面文案）。
保留两份时，必须在这里登记口径与理由，避免下一个人误以为可以随便改写其中一份。

| 已知的概念分歧 | 实现点 | 口径 / 处理 |
|---|---|---|
| 字节格式化 | `core/tools/Truncation.formatSize`（1024 进制、无空格，进工具输出给模型）/ `ui/components/Format.formatSize`（1000 进制、带空格，给用户看） | **刻意保留**：`core` 不得依赖 `ui`，两者受众与约定不同；新增字节格式化按所在层选其一，不要写第三份 |

**已知重复（待统一）**：

| 概念 | 实现点 | 处理 |
|---|---|---|
| 行切分（切分 + 去尾幻影行） | ~~`Truncation`×2 / `UnifiedDiff`~~ | ✅ 已统一为 `core/tools/Truncation.splitLines` |

新增工具函数前，先 grep 是否已有类似实现；已有则复用，无则新建并在 §1 索引里登记。

## 5. 跨模块不变量（先看「违反症状」，再看守护）

> 改代码前先对号入座：这条不变量由谁机械守护？没有守护的，评审时必须自己盯。
> 「症状」一列是检索入口 —— 线上 / 测试出现该现象时，先怀疑对应不变量。

| 不变量 | 违反症状 | 机械守护 |
|---|---|---|
| 插件契约二进制兼容（成员默认实现 + `-Xjvm-default=all-compatibility`） | 升级宿主后旧插件 `AbstractMethodError` 闪退（**所有**第三方插件一起崩） | `JvmDefaultCompatibilityTest`（`:plugin-api:test`） |
| 插件装载不得阻断宿主 | 坏插件 / 缺类导致启动失败、界面白屏 | `DynamicPluginHost` 失败收敛 + `DynamicPluginHostTest` |
| 会挂起等待用户的路径必须有超时 | 子智能体永久挂起、卡片永不消失 | `PendingUserGateTest`（机制层：超时 / 排队不计入 / 会话结束收尾）+ `ApprovalGateTest` / `AskUserGateTest`（两个闸门各自的语义与计时） |
| 请求前缀跨回合字节稳定 | 缓存命中率断崖、费用上升 | `RequestAssembler` 分段 + `CacheInspector` 面板 |
| 历史修复幂等、且「本就干净时返回同一个实例」 | 每次请求都重写并落盘一遍历史；修过的历史再修一次会改动前缀字节 | `HistorySanitizerTest`（`assertSame` 断言，不用内容相等） |
| 停止期间排队的消息必须被接上，且 STEER 不许被出队 | 用户点停止后再发的消息永久滞留在队列里；或插话被 `runLoop` 之前的取走丢掉 | `TurnQueueTest`（决策）+ `AgentSessionInterruptTest` 的两条队列用例（时序） |

| 文档与代码一致（段落清单 / 状态枚举 / `strings.xml` 死条目 / 内核中文清单） | 代码修对了、文档还停在旧版本；改名后文档没人跟；`strings.xml` 留着无人引用的条目 | `DocsConsistencyTest`（A6） |
