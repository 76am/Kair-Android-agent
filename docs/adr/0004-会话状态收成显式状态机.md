- **前置**：`docs/tasks/archive/P0-1-主循环测试底座.md`（B5）已完成 —— 没有主循环集成测试，本 ADR 的验收无法被证明
- **关联**：`docs/adr/0003-停止要等取消收尾结束.md`（本 ADR 的直接动因）、`docs/架构评估-2026-10.md` §3.2

## 背景

会话运行状态目前由**四个量交叉表达**：

- `_status: MutableStateFlow<SessionStatus>`（`IDLE` / `RUNNING` 两态）
- `_stopping: MutableStateFlow<Boolean>`
- `_compacting: MutableStateFlow<Boolean>`
- `pendingRuns: AtomicInteger`

（`AgentSession.kt`，`launchSerial` / `abort` / `isBusy` 一组函数。）

ADR 0003 为了解决「停止 → 抢发」竞态引入了 `_stopping`，代价正是多了一个
必须与 `_status` 手工保持一致的状态。当前形状的问题不是「写错了」，而是
**「不一致」这个状态在类型上是存在的**：

- 四个量必须随时一致，但**没有任何断言**在守；
- 置位与复位的顺序错一行（如 `abort()` 里先读 `job` 后置 `_stopping`），
  就会永久卡在「正在停止」：界面转圈顶掉停止键、发送永久禁用、重开同一会话仍复现；
- `isBusy` 是四个量的布尔表达式（`isRunning || _compacting || pendingRuns > 0`），
  每加一个新状态就要回来改这里，且改漏了不报错。

`docs/架构评估-2026-10.md` §3.2 的判断：**这是唯一会稳定复发的缺陷族**，
因为失败模式是概率性的、且只在真机出现——单测抓不到，代码审查看不出来。

## 决策

1. 用**单一封闭状态**表达会话的运行状态：

   ```kotlin
   // 形状示意，最终命名与是否携带字段以实现提示词为准
   sealed interface TurnState {
       data object Idle : TurnState
       data object Running : TurnState
       data object Stopping : TurnState   // 取消信号已投递，收尾仍在进行
       data object Compacting : TurnState
   }
   ```

   具体实现命名以 `docs/tasks/archive/P2-1-会话状态机.md` 为准（该文件给出完整形状与转移表）。

2. **唯一转移函数**：状态只能由一处写入（`transition(next)`），外部一律只读。
   `_status` / `_stopping` / `_compacting` 三个 `MutableStateFlow` 全部删除，
   对外仍暴露 `StateFlow<TurnState>`（以及为兼容现有消费点保留的派生只读属性）。

3. 转移表里**显式列出非法转移**的处理（记录 + 保持现状，而不是静默覆盖）。
   「不合法组合」这一族状态在类型上消失：不存在「`IDLE` 且 `stopping == true`」。

4. `pendingRuns` 降级为 `TurnState` 的**内部实现细节**，不对外暴露，不参与语义判断。

5. 同一提交内**删除**被替代的四个状态量与相关开关（`AGENTS.md` §10.3），
   不做「新旧并存 + 开关切换」。

## 后果

**收益**

- 「状态不同步」这一族缺陷在类型上无法表达，是唯一能**减少**未来 bug 的动作；
- `abort()` 竞态的修复不再依赖「顺序写对了」，而是「写不出来」；
- 新增状态只需改一处转移表，「改一处漏三处」消失。

**代价**

- `ChatScreen` / 停止键 / 发送禁用 / `isBusy` 等消费点要一次性改写（评估 A1 估 2–3 天）；
- 状态是 `core` 内部类型，**不进 `plugin-api`**，因此不涉及 `KairApi.VERSION`；
  但凡有 UI 直接消费布尔量的地方都要改，改动面比看上去大；
- 过渡期如果不小心做成「新旧状态并存 + 一个开关」，就退化成补丁
  （`AGENTS.md` §10.2 的硬标准：能靠开关复现的旧问题，等于没修）。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 保留四个量，补一组一致性断言 | 断言只能发现不一致，不能消除不一致；且断言本身要维护，等于把状态机用断言重写一遍 |
| 加第五个布尔量表达新状态 | 正是本次要消灭的形态；组合数随布尔量指数增长 |
| 用枚举 + 允许任意组合（`data class Status(running, stopping, compacting)`） | 组合仍能表达非法状态，只是换了个写法 |
| 直接重写 `AgentSession`（不等 A1） | 1638 行一次重写无回归网；须先有 B5 测试底座，且 A5 的拆分应在 A1 之后 |
