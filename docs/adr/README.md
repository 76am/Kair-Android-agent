# 架构决策记录（ADR）

> 只记**不可逆、或回退成本很高**的决定。一般的实现选择写进 KDoc 或 PR 描述即可，
> 不要往这里灌「日志」。

## 什么时候写

- 决定会**限制未来的选项**（平台约束、目录结构、契约形状）；
- 有一个「看起来更简单」的替代方案被否决，而理由不是显而易见的；
- 决定会改变 `AGENTS.md` / `docs/架构与内核边界.md` / `docs/团队分工与交付流程.md` 的条款。

## 格式

每条一个文件，命名 `NNNN-短横线标题.md`，结构固定五段：

```
状态 / 日期 / 背景 / 决策 / 后果（含代价与被否决的选项）
```

状态只有四种：`提议` / `已接受` / `已被取代（指向新编号）` / `已废弃`。
**不修改已接受的 ADR 的结论**——要改就新写一条并把它标为「已被取代」，历史要能读出来。
