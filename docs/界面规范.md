# Kair 界面（Compose）规范

> 配合 `AGENTS.md` 与 `docs/代码规范.md` 使用。目标：让界面改动**可预测、可复用、不膨胀**。
> 本文件管「怎么写界面」；「能复用什么、新增能力改哪里」见 `docs/代码索引.md`。

---

## 0. UI 改动先出草稿（2026-11-21 立）

- **先问、再出、pass 后才开工**：任何用户可见的 UI 改动（布局 / 配色 / 组件形态 / 交互动效），
  动手前先问负责人「要不要先出 HTML 可交互草稿」。负责人说要，就先出草稿；
  **草稿 pass 之前不改 Compose 代码**。
- 草稿要求：单文件可交互、明暗两套、关键状态可切换；**少写字**，只放差异与判据；
  放 `/workspace/design/<slug>/`，不进仓库、不跑构建。
- 纯文案 / 1dp 级间距微调可以先问一句再直接改；其余一律走草稿。

## 1. 文件组织

- **一个屏幕一个包**：新屏幕一律放 `ui/screens/<screen>/`（如 `ui/screens/chat/`、`ui/screens/settings/`）。
  - 外壳（`XxxScreen`）单独成文件：只管状态、`Scaffold`、顶栏、对话框挂载。
  - 其余按职责拆分：消息渲染、输入区、面板、卡片各成文件。不要把所有东西堆回一个文件。
  - 存量扁平文件（`PluginsScreen.kt`）不单独做纯搬迁提交；**发生结构性改动**
    （新增面板 / 拆文件 / 改外壳）时顺手迁入包。纯配色、间距、文案微调不强制迁移。
- **公共可复用件**一律放 `ui/components/`。
- **内置插件**放 `ui/plugins/builtin/`（一插件一文件）；`ui/plugins/` 只放共享渲染辅助（槽位、设置面板渲染器）。
- **软上限：单文件约 500 行**，超过就该拆；函数长度阈值见 `代码规范.md` §4
  （普通 ≤ 100 行、Composable ≤ 200 行）。
- **超限名单与登记值以守卫为准**：`SourceSizeGuardTest`（文件级）与 `MethodSizeGuardTest`
  （方法级）维护白名单和实测行数，本文件不抄数字（会漂）。目前需要优先拆的存量大文件是
  `ui/screens/chat/ChatScreen.kt`、`ui/screens/PluginsScreen.kt`（`WorkspaceFilesPlugin.kt` 已于
  2026-11-05 U38 拆出 `WorkspaceFilesUi.kt`，降到 196 行、移出名单）；是否超限、当前多少行看守卫。
- 输入区已从 `ui/screens/chat/Composer.kt` 拆到 `ui/screens/chat/ComposerInputBar.kt`
  （排队区与命令建议仍在 `Composer.kt`）；后续拆别的屏幕同样按「先拆再改」。

## 2. 复用优先（强制）

动手写界面前，先查 `docs/代码索引.md` 的「可复用件索引」。

- 折叠区、面板卡、设置行、格式化函数**已有实现，不得重写**（同一 UI 原语的两套渲染路径属
  `代码索引.md` §4 的违规；纯代码重复、行为一致则不强制抽象）。
- 若原实现是 `private` 而你需要跨文件用：把它提升到 `ui/components/` 并改为 `internal`，**而不是复制一份**。
- 例外情况必须说明理由，否则视为重复代码。

（`ArchitectureGuardTest` 只能机械地守住 `core` 的越界；UI 层的复用靠这条纪律 + 评审。）

## 3. 屏幕外壳

- 用 `Scaffold` + `TopAppBar`；返回用 `TextButton { Text(stringResource(R.string.action_back)) }`。
- **顶栏动作随能力走**：动作来自插件贡献点，插件被禁用时贡献点会被回收——按钮应连带隐藏，避免留下「点了没反应」的摆设。
- 键盘弹出时注意 `imePadding`：先消费 `Scaffold` 已施加的系统栏内边距，再补键盘高度，**不要重复计算**导航栏（见 `ui/screens/chat/ChatScreen.kt`）。
- 自动跟随最新内容的列表，除了监听末条高度变化，还要在**可视高度变化**（键盘弹出 / 收起）时贴底 —— 静态列表没有重组触发补滚，只监听末条会把键盘引起的视口收缩漏掉（见 `AutoScrollToLatest`）。
- **轻点输入框等于明确的贴底意图**：用户上翻看历史后点输入框，列表要回到最新再跟随键盘；不要只依赖「本来就在贴底态」才跟随。用点击交互（`PressInteraction`，忽略长按）而不是 `onFocusChanged` —— 键盘已弹出时再点输入框不会再次改变焦点。显式请求用计数触发，别用「贴底后等 `atBottom` 变 true」：键盘 inset 动画会把视口压小，这个推导可能永远等不到。
- 列表离开底部时，在输入框上方的列表底部居中给一个可见的 ↓ 按钮，点击即贴底。**可见性挂「用户手动上翻」（`following == false` + 24dp 迟滞），不挂 `!canScrollForward`** —— 后者在流式输出期间每帧翻转（内容长高 → 立刻可滚 → 补滚落位 → 又到底），按钮会以推送频率（约 15Hz）频闪；判据见 `rememberJumpToBottomVisible`。「贴底」动作共用 `LazyListState.requestScrollToLatest`，不要各写一套偏移。按钮是悬浮控件，颜色用 `floatingContainer` / `onFloatingContainer`（见 §10），不要用 `primary`。形态用 `SmallFloatingActionButton` + `CircleShape`，**不要给 `FilledIconButton` 手加 `Modifier.shadow`**：阴影会落在 48dp 点击区上、与 40dp 本体不同心，真机底部会露出半圈方角。
- **瞬态提示条（Snackbar）挂在消息区顶部，不用 `Scaffold` 的默认宿主**（2026-11-09 负责人反馈：压缩成功 / 「已删除这条消息」弹出时短暂遮住底部按钮）。原因：本页的输入区与 dock 是 content `Column` 的尾部子项、**不在 `bottomBar` 槽里**，默认宿主落在屏幕最底＝正压「停止 / 发送」和 dock 那一排。改挂列表 `Box` 的 `Alignment.TopCenter` 后，被盖住的是**列表最上面那一截**：上翻时是最早那条可见消息的上沿（可能是正文，也可能是卡片底部含「⋯」那一行 —— 卡片在有可执行动作时整块挂长按，见下两条），贴底且最新消息高过视口时是长回答靠上的那一段；都不是用户正在读的尾部，提示条几秒后自消失。**不要**因为「顶部也会盖住内容」就挪回 `Scaffold` 默认宿主：那是把「压住停止 / 发送」换回来。
- **每条消息卡片都要有长按菜单的可见入口「⋯」**（负责人 2026-11-01 追加：用户气泡也要有，不能只有 agent 气泡有）。它**只允许一处实现** —— `ui/screens/chat/MessageCardActions.kt` 的 `MoreActionsEntry`，两种气泡都调它（`MessageCardActionsGuardTest` 钉：字面量「⋯」归零、入口使用 `PluginGlyph.More` 线稿，两处卡片各自调组件）。**唯一的例外**是步分隔线上的「⋯」（`TurnStep.kt` 的 `StepDivider`，73766246）：它弹的是**步级**菜单（整步删除 / 重试），语义与卡级入口不同，故自绘 `PluginGlyph.More` 线稿、不复用组件，但同样吃 48dp 命中盒下限（视觉 24dp 圆底，与卡级入口共用 `MoreActionsEntrySize`；行高固定 20dp，`size()` 会被约束夹回，用 `requiredSize(MoreActionsHitSize)` 越出行界、`CenterVertically` 居中，触点上下各出 14dp）。摆放口径分两种：
  - **卡片有每卡必现的底部标签时，入口与标签排在同一个 `Row` 里**（用户气泡：发送时间 + 入口，`verticalAlignment = CenterVertically`，整行 `align(Alignment.End)`）。不要用角标叠加在时间上 —— 那正是 U24 报的「标签与 `⋯` 不平行」；也**不要给这一行加 `weight(1f)`** —— 它会把 Row 撑成全宽，只发一行字的气泡也会被拉满整屏（2026-11-05 负责人真机反馈）。用户气泡本身**宽度随内容收、整包贴右**（左侧留 40dp），只有 agent 气泡全宽。
  - **agent 气泡把入口放进内容底部的 `AgentFooter` 行**（结束原因 / 错误重试在左，「⋯」在右；三样都没有时整行不渲染），入口按 12dp 内容内边距离圆角有距离、与状态标签垂直平行。**不要再做右下角角标叠加**：入口会落在圆角上、与标签不平行，长文本还会被压住（2026-11-05 负责人真机反馈）。入口尺寸由 `MoreActionsEntrySize`（24dp）统一。
  - 两条共同规矩：**正在流式的那一条不渲染入口**（那时菜单里可用的只有「选取文字」，卡片本身又每帧在变）；**没有可执行动作时既不显示入口也不挂长按手势**（空菜单等于假入口）。视觉取 **24dp 圆形**（2026-11-05 负责人拍板从 48dp 缩小：48dp 塞在紫底里让一行字的气泡过大），外圈补 **48dp 命中盒**（U105，视觉不变）；本体是一个**有底色的圆**（`surfaceDim`），按下走下面的 state layer 口径（2026-11-20：不再靠圆形涟漪，也不留无底色的透明命中区 —— 两者都会让用户看不出这里能点）；**图标用 `PluginGlyph.More` 线稿**（U105，不再用文字字形），并带 `chat_more_actions` 的 `contentDescription`。

### 3.1 输入区（`ui/screens/chat/ComposerInputBar.kt`，排队区在 `Composer.kt`）

- **形态**：整条输入区是一枚 26dp 圆角软底胶囊（`surfaceContainerHigh`），附件 / 停止 / 发送都在胶囊内；
  输入框用 `BasicTextField`，不再用带边框的 `OutlinedTextField`。附件、停止、发送的布局盒统一 48dp、
  与输入框最小高度对齐，发送键是 40dp 实心圆；单行时同轴居中，多行时按钮贴底。
- **提交键只有一个**：纸飞机 = `send`，忙时入 `FOLLOW_UP`、**本回合结束后**作为新回合发出，空闲时直接起回合。
  **不要加第二个「发送」形状的按钮**：U22 曾按需求 §3.2 放了一个三角（`Icons.Filled.ChangeHistory`）做插话，
  负责人 2026-11-01 指出那看着就是两个发送键，而且该图标实际是「时钟 + 回转箭头」、**不是需求说的描边三角**。
  插话因此挪进排队区（下一条）。判据：`GuideComposerTest` 的源码守卫（`submit` 里只许 `session.send(`、
  不许再出现 `SubmitMode`）。
- **停止键分两态**（U58 ②）：`Running` 时是与亮起发送键同色同形的实心圆 —— 48dp 布局盒里
  40dp `FilledIconButton`（默认 `primary` / `onPrimary`）+ 18dp Stop 图标（U105 返工：恢复
  主线样式，自绘白圆在浅色板上与发送键几乎同色）；`Stopping` 仍是 18dp 转圈、不可点，两态可区分。
  **停止键不叠转圈**（2026-11-07 负责人改）：状态条已有一个 14dp 转圈，按钮再转一个看着花；
  「还在动」的信号由状态条独家承担，不能只靠最后一条 assistant 卡片 —— 工具结果回来到下一段输出之间它已经不转了。
- **运行态状态条**（`AgentActivityStrip.kt`，U58 ②）：输入胶囊**上方**一行「14dp 指示位 + 文案」，
  常驻不消失。前半段只读 `turnState`：`Running(compacting = true)` → `chat_compacting`、
  `Running(compacting = false)` → `chat_running`、`Stopping` → `chat_stopping`、
  `Idle` / `Busy` → `chat_state_idle`（待机）；**有待审批或待回答卡片时整行不渲染**
  （卡片本身就是「在等你」，再写「正在运行」会误导）。
  U115 起均速后缀是**所有状态的常驻后缀**，不再只在待机行拼：工具执行 / 压缩 / 停止
  这些没有实时值的状态也要带；实时值（`chat_speed_live`）只在生成时前置，顺序固定为
  「状态 · 实时 · 本会话」。**后缀内容是本会话均速**（`ChatSpeed.sessionSpeedText` →
  `chat_speed_session_avg_label`，U115 返工：负责人要的是整段会话的均速常驻，不是刚结束那一轮），
  本轮那个数仍在回合折叠头（`chat_speed_turn_avg`）与上下文面板（`chat_speed_turn_avg_label`），
  不丢数据；本会话还没有任何已观测响应时不写 0。`liveRegion = Polite`，
  TalkBack 只报状态变化；单行不换行，超长时只省略速度后缀（状态词永远保留）。
- **排队区每条三个动作**：铅笔「撤回编辑」（回填输入框 + 图片 → 从队列移除 → 聚焦输入框，**不得重复发送**）、
  三角「改为立即插话」（`promoteToSteer`：先移除再 `steer`，只对 `kind != STEER` 的行显示 ——
  已是插话的再按一次只会挪到队尾）、垃圾桶「丢弃」。
  不要只留一个「×」：用户分不清是撤回重编辑还是丢掉。改道走 UI 侧既有 API，
  **不新增内核方法**（代价是这条落到 STEER 队列末尾，保序需给内核加「改 kind」，属另一档改动）。
  两个动作都先判**那条仍在队列里**（读 `queue` 实况，不读点击前的旧帧），否则「改道」会变成当场重发。
- 三角图标自绘 `res/drawable/ic_queue_steer.xml`（描边圆角向上三角），经 `painterResource` 引用 ——
  Material 扩展库里**没有**形状正确的向上描边三角，别再找一个「差不多」的图标顶替。
- 停止收尾期间**仍可发**：消息入 `FOLLOW_UP`，收尾结束由 `drainQueueAfterStop` 接上；
  禁发会在工具不响应取消时把用户永久锁在输入框外。
- **有挂着的引导消息时，点停止要先确认**（`StopConfirm.kt`，行为由 `StopConfirmTest` 守）：内核 `abort()` 的第一件事是
  `clearQueue()`，排队的用户消息会被丢掉 —— 所以丢弃必须发生在**点下去之前**的确认里，事后提示等于没说。
  弹窗只列用户自己的排队消息（系统通知不参与，沿用 U18 口径），前 4 条 + 余量如实报数，长文截 80 字，
  纯图片那条给「（仅图片）」占位而不是静默消失。按钮是**「仍要停止 / 继续运行」**，**不要写「取消」**——
  在这个语境里它会被读成「把这些消息取消掉」，语义正好相反。没有排队消息时**不弹窗**，别给多数停止多加一次点击。
  列表读 `queue` 的**实况**而非点击前的快照：确认期间回合可能自己跑完、队列排空时列表要跟着变。
- 输入区整段状态（预览 / 输入框 / 停止 / 提交 / 贴底请求）都收在 `ComposerInputBar.kt` 的
  `ComposerInputBar`，`ChatScreen` 只传状态与回调；别再往 `ChatScreen` 里加输入相关的局部状态。
- **系统通知不进排队区**（U18）：`visibleQueue` 过滤 `isSystemNote`，后台通知仍走 `steer(systemNote = true)`。

### 3.2 会话抽屉（推屏式，U115）

- **两层，不是覆盖**：`ui/components/PushDrawer.kt` 替换 M3 `ModalNavigationDrawer`。下层抽屉背景铺满
  整屏；上层页面整块用**布局位移**（`Modifier.offset`）右移 **65%** 屏宽（`PUSH_DRAWER_FRACTION`），
  **不缩放、不套 `graphicsLayer`** —— 带裁剪 / 投影的层在真机上会把页面内容一起吃掉（2026-11-23
  真机：无项目页只剩一条空白在滑）。收起时位移严格回到 0。
- **抽屉内容列只占可见的 65%**：由 `PushDrawer` 用 `fillMaxWidth(0.65f)` 限制，`SessionDrawerContent`
  只排内容；右侧 35% 会被页面盖住，控件（+ / 时间 / ⋯）必须留在可见区，不许按整屏宽度排版。
- **手势与返回**（U115 返工第三轮）：顶栏 ☰ 或从**整屏任意位置右滑**打开；展开时**点页面区域** /
  **整屏左滑**（往回拨约 13% 屏宽即收起，`PUSH_DRAWER_CLOSE_THRESHOLD`）/ 返回键关闭。
  **抽屉内部的轻点一律不收抽屉**（`shouldCloseOnTap` 只认 `x >= 页面左缘`）：会话条目、分段、
  项目行、「⋯」、列底新建、以及触发重命名 / 删除弹窗的长按都在抽屉里，轻点完就把抽屉弄没
  等于逼用户重开。
- **起拖裁决只判一次**（`drawerDragClaim`，`PushDrawerTest` 钉）：行程过 **16dp**
  （`PushDrawerDeadZone` = 平台 touchSlop）后，**位移或速度任一更横**（`|dx| > |dy|` 或
  `|vx| > |vy|`）就算横滑，再要求**方向符合状态**（收起态只接右滑、展开态只接左滑 ——
  输入板下沿 chip 行往左滚仍归它）；判给列表（`Rejected`）就这条手势彻底不碰抽屉，
  不留「列表先滚、抽屉后跟」的糊态。**拇指是弧形拖的**，累计纵向分量必然一路涨，
  所以只看位移的方向比救不了手感（1.2 倍、1.0 倍各栽一轮），**速度分量才是意图**。
- **两个必须用的 API**（都是真机坑）：累计位移用 `positionChangeIgnoreConsumed()` —— 用
  `positionChange()` 时转录区 `LazyColumn` 一开始滚，我们拿到的增量就被消费清零，抽屉永远
  攒不够行程（「识别成上下滑」的真凶）；拖动仍走 `scope.launch { progress.snapTo(...) }`，
  只保留**一个**拖动写入任务并在松手前取消（排队中的 snapTo 会把随后的吸附动画取消掉）——
  **不要用 `Animatable.mutate`**，那是 animation-core **1.8** 才有的，当前 BOM 2024.10.01 解析到
  1.7.5，编不过（javap 铁证：1.7.5 的 `Animatable` 只有 `snapTo` / `stop`）。手势层是整屏父层，
  **不靠 `isConsumed` 让位**（1px 纵向分量就会被消费，靠让位等于整屏拉不开）。
  不消费时列表 / 按钮照常工作。不做左滑删除。
- **位移必须乘 65%**：`PushDrawer` 的手势进度是 0..1，位移 = `屏宽 × 0.65 × 进度`；
  拖动换算的分母也是 `屏宽 × 0.65`（页面实际行程），否则会整屏右移 / 拖得比手快。
  这两条由 `PushDrawerTest` 的纯函数钉住（返工就是漏乘 65% 导致的整屏右移）。
- **不压暗主界面**：不做 scrim；层次靠抽屉底色（`surfaceContainerLow`）与页面底色（`surface`）的

## 6. 对话框

- 确认类一律用 `AlertDialog`，四段齐全：`title` / `text` / `confirmButton` / `dismissButton`。
- **破坏性、不可逆或有副作用的动作必须先确认**（如压缩上下文、关闭核心插件、强制安装不兼容插件）。
  文案要解释「会发生什么」，不要只写「确定吗」。
- 取消按钮文案统一用 `action_cancel`。**例外**：停止确认的 dismiss 是「继续运行」
  （`chat_stop_confirm_keep`），因为「取消」在那里会被读成取消排队消息；见 §3.1。

### 6.1 待决定卡片（审批 / 提问）

审批 / 提问不是模态对话框，渲染在输入区上方（`ui/screens/chat/ApprovalCards.kt`）。规则：

- **颜色**：审批用 `errorContainer`（朱红闸门），提问用 `secondaryContainer`（蓝容器）；容器形状 `MaterialTheme.shapes.large`。
- **抬头**：30dp 圆形徽标 + `titleSmall`；提问卡的「跳过」放在标题行右侧，不要塞进输入行。
- **选项**：用 `Surface(shape = shapes.medium)` 的行 + 右箭头，不要用全宽描边按钮。
- **输入**：文本域（`shapes.small`）+ 44dp 实心发送圆同一行。
- **提示**：超时提示放卡片底部；审批参数放独立 `surface` 圆角块，限高可滚动、可选中复制。
- **动作语义不变**：审批四个决定（允许 / 本会话 / 永久 / 拒绝），提问可跳过；不要为了视觉合并或隐藏入口。

## 9. 状态与副作用

通用协程 / 阻塞 IO 规则见 `代码规范.md` §5；界面侧只补充：

- 会话 / 运行态用 `StateFlow` + `collectAsState` 暴露。
- **插件贡献组合期直读**（U46；B 评审补 `slots()`）：`panels()` / `actions()` / `commands()` / `settingsSections()` / `settingsPanels()` / `slots()` 是注册表 Compose 状态的导出快照，直读即自动订阅；`remember` 住（含 `remember(refresh)`）会在装 / 卸 / 启停后陈旧，`PluginContributionFreshnessTest` 钉死这条。**只有磁盘态**（动态插件文件清单 / 版本 / 工具开关落盘结果）与**非 Compose 态导出**（`tools()` / `toolEntries()`——`tools` 是 `CopyOnWriteArrayList`，直读不订阅，新鲜度只能靠 `refresh++`）才用 `refresh` 计数重建。
- **一次性事件**（如「上下文已压缩：X → Y」）由**会话侧消费**（`AgentSession.consumeLastCompaction()`），不要只靠界面级 `remember` 去重——界面对象会重建，去重会丢失并反复弹。
- **面板层改数据，必须把刷新信号透进子列表**（U79）：子列表的状态 key 只有 `backend` / `dir` 时，面板层在**根目录**做的批量操作（回收站「一键清空」）两个 key 都不变 → 列表停在旧快照（摘要变了、条目还在）。`FileList` 的 `refreshKey` 因此**故意不给默认值**：每个调用点都要表态，有面板层变更就传自己的计数，确实没有就显式写 `0`。这条是 U53R「状态和它对应的刷新信号必须同源」的同族 —— 只推自己那个计数，等于另一个信号源没人知道。

## 10. 视觉

- 颜色、字号、圆角一律取 `MaterialTheme.colorScheme` / `typography`，**不要硬编码** `Color(0xFF…)` 或 `fontSize`。
- **强调色只有两支**（U106）：蓝（`primary`）归 agent / 当前 / 成功，朱红（`error`）归你 / 危险 / 失败。
  黄铜已退场；`tertiary` 只是 `primary` 的别名（M3 槽位必须填），新代码不要直接用它，
  也不要再引入第三支强调色。层级其余部分交给中性面与描边。
- **按角色取色，不要按「看起来像」取色**。先查下表；新增按钮 / 卡片先判断它属于哪一类，不要从相邻组件抄颜色：

| 用途 | 色槽 |
|---|---|
| 主操作（发送、确认、选中） | `primary` / `onPrimary` |
| 当前 / 正在跑 / 成功（回合焊点、当前默认徽标、后台任务成功） | `primary` |
| 悬浮控件（回到底部 ↓、首页新建 +） | `floatingContainer` / `onFloatingContainer`（白底墨字，靠 `outline` 描边与阴影站住，不跟 `primary` 抢） |
| 提问卡 | `secondaryContainer` / `onSecondaryContainer`（与 `primaryContainer` 同色） |
| 审批卡 | `errorContainer` / `onErrorContainer`（U97 起用朱红族；压缩检查点用 `primaryContainer`） |
| 危险、错误、失败、被拒 | `error` / `onError` |
| 工具成功、diff 新增 | `successContainer` / `onSuccessContainer`（Theme 扩展槽；diff 新增行直接用 `primary`） |
| 用户气泡 | `surfaceContainerHigh` + `outlineVariant` 细描边（U102 起为中性纸面，不再用 `primaryContainer`） |
| agent 回合 | 正文流（无气泡、无轨道，73766246 起步界改折叠体内分隔线）；工具卡 `surfaceContainerLow` + `outlineVariant` |
| 输入条胶囊 | `surfaceContainerHigh` |
| 折叠块、排队区、命令建议 | `surfaceVariant` |
| 普通卡片（首页等） | `surfaceContainerHighest`（默认 Card） |
| 页面底色 | `background` |

- 新增或调整颜色必须在**明暗两套主题下各看一次**；悬浮面靠 shadow / elevation 与背景分离，不能只靠颜色。
  浅色抬升面按 U105 重配：面与白底 1.06–1.15:1、装饰描边 1.37:1，图标型控件的边界用 `outline`（≥3:1）。
- 全局圆角在 `ui/theme/Theme.kt` 的 `KairShapes` 定义（extraSmall 8 / small 12 / medium 14 /
  large 18 / extraLarge 24 dp）；按语义取：输入框 / 紧凑 chip 用 extraSmall，菜单 / 列表行用
  small，卡片用 medium，气泡 / 面板块用 large，对话框用 extraLarge。新代码一律取
  `MaterialTheme.shapes`，不要再写死 `RoundedCornerShape(n.dp)`。
  **唯一的一次性形态值**是输入条胶囊的 26dp（需要接近半高的圆角，不适合塞进语义阶梯）。
- 间距用 `dp`，与相邻组件保持一致；相邻可点目标的间距 ≥8dp。
- 对话页槽位 chip 统一走 `ui/plugins/PluginSlots.kt` 的 `DockChip`，形状由**槽位区域**决定：
  顶部 `SlotArea.TOP` 已停用（U101）；底部 `SlotArea.BOTTOM` 用 `30.dp + MaterialTheme.shapes.extraSmall`
  （对齐内置「模型 / 思考强度」），外圈统一补到 **48dp 命中盒**（U105，视觉尺寸不变）。
  改 chip 尺寸 / 形状只改传值，不要在插件里另造样式。
- 上下文圆环单独一档 **43dp**（U115 返工：**环外径 = 可见圆底外径**，环贴着底的边；
  上一档 34dp 看起来是「小环浮在一枚大圆钮上」），43dp 留出约 33.4dp 内空，`100%` 不压线。
  中心给百分比，字号按外径派生（`size × 0.30`）并换算成固定物理大小（不随系统字号放大）；
  精确值同时进 `contentDescription` 与点开后的上下文面板。
  **可点的环必须有可见圆底**（2026-11-20；U115 加强，返工后与环同径）：`DockGauge` 在 `onClick != null`
  时垫一层 `ColorScheme.gaugeDisc`（浅色 `surfaceVariant`，与旁边 chip 同材质；深色 `surfaceContainerHighest`，
  比输入板亮一档），**可见圆底 = 环外径**（贴紧，不再缩 10%），命中区 = 环 + 6dp且仍不小于 48dp；
  轨道必须同时换成 `ColorScheme.gaugeTrack`（浅色白、深色沉），否则轨道与圆底同色会消失。
  只报读数、不可点的环不垫底、轨道仍用 `surfaceVariant` —— 「有底 = 能点」这条口径不能糊。
- **按下反馈只有一个口径：state layer，不用 M3 水波纹**（`ui/components/PressLayer.kt`，2026-11-20）。
  波纹画在**命中框**上、按命中框形状铺开，而命中框按 U105 一律补到 48dp、本体常常只有
  24–34dp，于是按下是一块比本体大一圈、还盖到邻位的方形亮斑（真机反馈：上下文圆环、「⋯」、
  坞 chip 全是这个形态）。写法固定三步：`clip(本体形状)` → `background(本体底色)` →
  `clickable(interactionSource, indication = null)`，再 `pressLayer(rememberPressLayer(interaction), onSurface)`；
  压层排在 `clip` 之后才会跟本体同形。数值沿用折叠头与工具卡：10% `onSurface`，按下 90ms / 松开 150ms。
  已经按这个口径改的：`TurnFold` 折叠头、`TraceBlock` 工具卡、`DockChip`、`DockGauge`、
  `MoreActionsEntry`、`StepDivider`。新控件不要再引 `LocalIndication` 或手画 ripple。

## 12. Markdown 渲染（2026-11-21 立）

- **只接 assistant 正文**：`ui/components/markdown/` 是唯一实现；用户消息保持纯文本。
  折叠体里的中间回合也保持纯文本 —— 折叠区是轨迹预览，不做二次排版。
- **解析范围**：标题 / 段落 / 列表 / 引用 / 分隔线 / 围栏代码 / 表格；行内粗体、斜体、
  删除线、行内代码、链接。认不出的写法退回段落，不丢字。
- **复制口径**（与长按菜单同一套）：整条消息复制 = 原始 Markdown；表格卡复制 = 该表
  的 Markdown 源码；代码卡复制 = 纯代码。**表格不提供下载**（2026-11-21 负责人明确去掉 CSV 下载）。
- **长按口径不变**：长按气泡任意位置仍只弹消息菜单（选取文字 / 复制 / 重试 / 删除）；
  表格卡的复制 / 放大是单击按钮，不改变长按层级。链接用 `LinkAnnotation`，不用会
  吃掉 down 事件的 `ClickableText`。
- **流式**：未闭合围栏照常画代码卡；最后一块表格未遇到空行时先画固定三行骨架，
  流结束或空行到达后再换真表格，避免半行抖动。
- **表格**：卡片头 48dp（复制 / 放大），列宽按内容量宽后按比例铺满，超出则横向滚动；
  第一列用等宽 / 次要色。放大走同尺寸表格的对话框，不另写一套渲染。
- **横向手势优先给表格**：只有真的超出卡片宽度时才登记（`HorizontalPanExclusion`），
  按下即接管这条手势，抽屉的整屏右滑不抢；短表不改变右滑开抽屉的手感。
