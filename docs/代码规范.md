# Kair 代码规范

> 配合 `AGENTS.md` 使用。规范的目的：让「能力皆可插拔 + 高缓存命中率」在代码层面可执行、可评审。

---

## 1. 工具链与语言

- Kotlin（JVM），Jetpack Compose 做 UI，`kotlinx-serialization` 做序列化，OkHttp 做网络。
- JDK **17**（其它版本会让 Gradle 崩，见 `AGENTS.md` 第 5 节）。
- 一律使用仓库自带的 Gradle wrapper（`./gradlew`），不要用系统 gradle。
- 排版由 ktlint（`org.jlleitschuh.gradle.ktlint`）机械守护，规则见仓库根 `.editorconfig`。
  排版由 ktlint 机械守护，`./gradlew ktlintCheck` 已包含在分支验证的统一命令里
  （`docs/团队分工与交付流程.md` §3.1，由 Kair 执行）；改写排版用 `./gradlew ktlintFormat`，不要手工对齐。
- 最低 API 26；`compileSdk = 35`、`targetSdk = 28`（锁 28 是为 proot 的 exec 权限，
  原因见 `README.md` 第 2 节 / `docs/架构与内核边界.md` 第 9 节，不要照「compileSdk 35」顺手把 targetSdk 也写成 35）。

## 2. 包结构与依赖方向

```
dev.kair.app
├── MainActivity.kt
├── app/        # 装配层：AppContainer（唯一装配点）
├── core/       # 内核 + 插件契约（不含任何 Android UI）
│   ├── model/  # 会话值类型
│   ├── ai/     # Provider 契约与传输层
│   ├── agent/  # 会话主循环、请求装配、system prompt
│   ├── tools/  # 工具契约与内置工具
│   ├── plugin/ # 插件宿主：注册表 + HookBus
│   ├── storage/# 存储契约与内置实现
│   └── settings/
└── ui/         # Compose 界面
    ├── screens/  # 一个屏幕一个包（界面规范.md §1）
    ├── components/ # 公共 UI 原语
    ├── plugins/  # 内置插件（贡献点在此实现）
    └── theme/
```

**依赖方向单向向下**：`ui → app → core`。

- `core` **不得** import `android.*`（UI 部分）、不得 import `ui` 包。
- 唯一例外：**持久化接缝** —— `core/settings` 需要 `Context` / `SharedPreferences`（构造注入、不静态持有；批次 9 起 `SettingsStore` 主构造收 `SharedPreferences`，JVM 假件接得上）、`core/storage` 需要 `Context` 时同样构造注入。逐条登记在 `ArchitectureGuardTest.allowed`。
- 需要新的跨层能力时，先想「它是不是一个插件」，而不是往内核加分支。

## 3. 命名

| 对象 | 约定 | 示例 |
|---|---|---|
| 类型 / 接口 | 大驼峰，名词 | `AgentSession`、`HookBus`、`ProviderTransport` |
| 接口（能力型） | 名词，不加 `I` 前缀 | `ContextStrategy`、`StorageBackend` |
| 贡献点类型 | 以 `Contribution` 结尾 | `CommandContribution` |
| 钩子 | 动词，`onXxx` | `onToolCall`、`onBeforeProviderHeaders` |
| 函数 | 小驼峰，动词开头 | `runToolCall`、`assembleRequest` |
| 常量 | 大驼峰或全大写视语境 | `StopReason.TOOL_USE` |
| 插件 id | 反向 DNS，小写点分 | `dev.kair.plugin.devtools` |
| 测试类 | 被测对象 + `Test` | `HookBusTest` |
| Compose 可组合函数 | 输出 UI（返回 `Unit`）用大驼峰；返回值（`String` / `Color` 等）保持小驼峰 | `CommandSuggestions`、`reasoningLabel` |

私有可组合函数在文件内定义时加 `private`。

> `@Composable` 只表示「可在组合中调用」，不改变命名约定：读取 `MaterialTheme` / `stringResource`
> 并返回值的辅助函数仍按普通函数用小驼峰（如 `toolPreview`、`diffLineColor`）。这也是 Compose
> 官方 API 指南的口径。注意 `.editorconfig` 的豁免覆盖**所有** `@Composable`，所以这条约定
> 目前只能靠评审兜底（机械守卫缺口见 `团队分工与交付流程.md` §2.3）。

## 4. Kotlin 约定

- 优先**不可变**：数据用 `val`、`data class`、`List` 而非 `MutableList` 对外暴露。
- 领域值类型用 `data class` + `@Serializable`（如消息、用量）。
- 代数类型用 `sealed interface` / `sealed class`（如内容块 `Part`）。
- 可空性表达意图：只有真会缺失才用 `T?`；不要用 `!!`。
- 顶层函数用于无状态工具（如 `parseArgs`），避免无谓的类包装。
- 不写「将来可能用到」的抽象；三行重复优于过早抽象。
- 注释写「为什么」，不写「是什么」。**行内注释与 KDoc 一律用中文**。
  - KDoc 用于跨文件 / 对外契约与「为什么这样设计」；行内注释用于解释当前这段代码的非显然决定。
  - 不要把函数签名翻译成 KDoc；能靠命名说清的事不写注释。
- **长度阈值**（软上限，超过就该拆；行数按源码行计，含空行与 KDoc）：
  - 单文件 ≤ **500 行**（UI 见 `界面规范.md` §1）。
  - 单方法 ≤ **100 行**；`@Composable` ≤ **200 行**（分两档的依据见 §4 末尾）。
    存量 13 个在 `MethodSizeGuardTest` 白名单里，只准减不准增。
  - 超限时按「状态 / 表单段 / 对话框 / 列表项」拆，不要靠注释分段硬撑。
  - 存量超限清单记在 `团队分工与交付流程.md` §2.3，随修随改。
  - 分两档的依据（2026-10-29 实测：1008 个普通函数 + 121 个 `@Composable`，
    nearest-rank（ceil(p·n)））：两类分布几乎不重叠 —— P50 ≈ 6 行 vs 32 行，P95 ≈ 41 行 vs 194 行。
    一刀切 150 在普通函数上只抓 4 个（≈P99.6，守卫等于半关），在 Composable 上抓 10 个
    （≈P91，把中等复杂度的屏幕也判成问题）。这些数会随拆分漂移，这里只用来支撑
    「两类差 5 倍以上、一刀切必错」这个结论；原始分布见 `docs/tasks/P5-2-方法长度守卫.md` §1。

## 5. 协程与并发

- 长生命周期工作在 `AppContainer` 的作用域启动，`Dispatchers.IO` 做阻塞 IO。
- 会话状态用 `StateFlow` 暴露，UI 侧 `collectAsState`。
- **不要把阻塞调用放在主线程**。插件目录的安装 / 删除 / 重扫同理（`Dispatchers.IO`）。
- 取消要传播：协程取消时，正在进行的网络请求也应被取消；工具执行里不要吞掉
  `CancellationException`（否则用户按「停止」会被伪装成工具失败并让模型继续重试）。
- 共享可变状态（如工具注册表）在装配期一次性构建，运行期只读；运行期若需写入，须有明确同步策略。
- **会挂起等待用户的原语必须有超时兜底**（审批 / 提问）：用户不操作时要结束等待、清理卡片，
  并向模型说明「该调用未执行 / 未作答」。子智能体尤其没人看着，不能无限挂起。
- 同一时刻只允许一个待用户决定的请求：并发请求用锁**排队**，不要静默拒绝，也不要互相顶掉卡片。

## 6. 插件编写规范

- 插件实现 `Plugin`，只暴露 `id` / `name` / `description` 与 `activate(ctx)`。
- `activate` 内**只做注册**，不要启动后台任务或做重 IO。
- 贡献点通过 `ctx` 注册；不要在插件里持有全局单例。
- 插件 id 使用反向 DNS；内置插件用 `dev.kair.plugin.*`。
- 插件必须能在**没有该插件**时，宿主仍正常工作（可降级，不可阻断）。
- 插件装载失败（清单错误、dex 链接错误、`activate()` 抛 `Error`）必须收敛为可展示的失败条目，
  不允许冒泡打断启动或让界面崩掉（见 `DynamicPluginHost.loadFailures`）。

### 6.1 插件契约 ABI

`plugin-api` 的契约是**跨编译单元**的 ABI（第三方插件独立编译，不随宿主重编）：

- 契约接口新增成员**必须带默认实现**，且默认实现要能独立工作 —— 否则旧插件全部
  `AbstractMethodError`（见 `AGENTS.md` 2.1）。
- 修改 / 删除已有成员签名属于破坏性变更：提升 `KairApi.VERSION`，同步
  `docs/插件接口契约.md` 第 10.5 节。
- 契约成员不要依赖宿主新增的内部状态；默认实现里不得引用插件未实现的东西。
- 改动契约后必须跑 `:plugin-api:test`，`JvmDefaultCompatibilityTest` 会校验默认方法
  真的是 JVM default（而不是只生成 `DefaultImpls`）。

## 7. 钩子规范（重要）

钩子**必须是纯函数**：

- 无副作用、幂等、结果只依赖入参。
- 返回 `null` 表示「不改写」，不要返回等价副本。
- 不得在钩子里发起网络 / 磁盘 / 时间读取等非确定性操作。
- `context` 钩子**只能追加**到消息列表末尾；不得改写、删除、重排已有回合。
- 拦截工具调用时，通过 `blockReason` 返回错误结果给模型，**不要**抛出异常中断会话循环。
- 唯一允许挂起的是 `tool_call`（等待审批）：**必须自带超时**，超时后按「未执行」返回
  `blockReason`。宿主 `ApprovalGate` 的超时只保护它自己的闸门，保护不了插件里的无限等待。

## 8. 缓存安全（违反即 bug）

见 `docs/架构与内核边界.md` 第 6 节。代码层面的硬性要求：

- 会进入 prompt 前缀的数据结构，序列化必须确定性：不要依赖 `HashMap` / `Set` 的迭代顺序，输出前显式排序。
- 前缀中不得出现时间戳、随机 id、会话内递增计数器（除非其递增本身是确定且只追加的）。
- 任何「易变」内容只能放到请求末尾。
- 新增会写进 prompt 的贡献点时，须在说明中交代对前缀的影响。

## 9. 错误处理

- **只在系统边界校验**：用户输入、网络响应、外部 API。
- 内部调用信任契约，不做过度的防御性判空。
- 网络/解析错误转成领域错误（如 `StreamEvent` 的错误态），由主循环统一处理。
- 不使用空 `catch`；吞异常必须留注释说明原因。

## 10. 字符串与国际化

- 面向用户：中文，进 `res/values/strings.xml`，代码里用 `stringResource(R.string.xxx)`。
- 面向模型：英文（工具 description、JSON Schema、system prompt、回灌文本）。**不要**翻译这些。
- 需要格式参数用 `%1$s` / `%1$d` 占位。
- **例外：内核产出的错误 / 会话状态文本**（如 `ErrorParser` 的分类说明）属于**会话内容**：
  会被持久化、可能随历史回灌，且 `core` 不得持有 `Context`。这类文本由 `core` 直接生成中文，
  **不进** `strings.xml`；UI 层只展示，不二次翻译。新增同类文本保持既有措辞风格。

## 11. 测试

- JUnit4（`org.junit.Test` + `org.junit.Assert`），放 `app/src/test/...`。
- 优先测**纯函数**：截断、路径解析、压缩、钩子链、目录注册。
- 每个被测单元一个测试类，命名 `XxxTest`。
- 测试要覆盖**边界**（空输入、越界、冲突）而非只覆盖 happy path。
- 涉及全局单例（如 `ModelCatalog`）的测试，必须在 `finally` 里恢复状态，避免相互污染。
- 新增钩子 / 贡献点 / 装配逻辑时，补对应单测。

---

## 12. 提交与评审

- 一个提交做一件事，信息用 `type(scope): subject`（如 `refactor(ui): 抽取插件页对话框`、
  `docs(lint): 修正豁免说明`）；`scope` 可省略（如 `docs:`），`subject` 用中文简述「改了什么」。
- 不提交构建产物、`.gradle`、本地配置。
- 改动内核边界 / 插件 API / 缓存契约时，**同一提交内**更新 `docs/`。
- 构建与单测**不由实现者自己跑**：`AGENTS.md` 第 5 节的统一命令由 Kair 在 PR 就绪后执行，
  实现者交付「验收点」与会红的用例（`docs/团队分工与交付流程.md` §3.1）。

## 13. 速查：应做 / 不应做

| ✅ 应做 | ❌ 不应做 |
|---|---|
| 新能力做成插件 / 贡献点 | 往内核加 `when (providerKind)` 硬分支 |
| 上下文改写只追加 | 改写/重排历史回合 |
| 前缀内容确定性排序 | 依赖 `HashMap` 迭代序 / 时间戳 |
| 面向模型的字符串用英文 | 翻译工具描述或 system prompt |
| `core` 不依赖 `ui` / `android.*` | 在 `core` 里直接持有 `Context` 单例 |
| 钩子是纯函数 | 在钩子里做网络 / 磁盘 / 读时间 |
| 同步更新文档 | 代码与文档不一致就交付 |
